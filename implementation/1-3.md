# 1. Introduction

The **AI-Powered LeetCode Visualizer** is an intelligent analytics platform designed to automatically synchronize a user's LeetCode submissions, analyze coding progress, visualize performance, and provide AI-powered learning assistance using **Retrieval-Augmented Generation (RAG)**.

Unlike existing LeetCode dashboards that only display statistics such as solved problems, contest ratings, and submission history, this project transforms coding history into an intelligent knowledge base.

The system allows users to interact with their own coding journey using natural language.

Instead of searching manually, users can ask questions such as:

- Explain my solution for Two Sum.
- Which Dynamic Programming questions have I solved?
- What topics am I weak in?
- Which Graph problems should I revise?
- Generate a study plan for FAANG interviews.
- Which questions are similar to Merge Intervals?
- What mistakes do I frequently make?

The application combines:

- Automated data collection
- Local database storage
- Interactive visualizations
- Artificial Intelligence
- Retrieval-Augmented Generation
- GitHub automation

to build a personalized coding mentor.

# Overview

The current project is an excellent analytics platform, but it only **stores** and **visualizes** data.

To transform it into an **AI-powered coding assistant**, we introduce a **Retrieval-Augmented Generation (RAG)** architecture.

The goal is **not** to train a new AI model.

Instead, we provide the Large Language Model (LLM) with the **right context** from the user's LeetCode history before it generates an answer.

This makes responses:

- Personalized
- More accurate
- Less prone to hallucinations
- Based on the user's own coding history

---

# 3.1 What is RAG?

Retrieval-Augmented Generation (RAG) combines two components:

1. **Retriever** → Finds the most relevant information.
2. **Generator (LLM)** → Uses that information to answer the user's question.

Instead of relying only on the LLM's knowledge, the system first retrieves relevant documents from your project.

Example:

```
User:
Explain my solution for Merge Intervals.
```

Without RAG:

```
LLM

↓

Generic explanation
```

With RAG:

```
SQLite

↓

Retriever

↓

Your Merge Intervals Solution

↓

LLM

↓

Personalized explanation
```

---

# 3.2 Why RAG Instead of Fine-Tuning?

Fine-tuning updates model weights and is expensive.

Your data changes every time you solve a new LeetCode problem.

Fine-tuning every day would be impractical.

RAG solves this by keeping data external.

```
New Submission

↓

SQLite Updated

↓

New Embedding

↓

Vector Database Updated

↓

AI Instantly Uses Latest Data
```

No retraining required.

# 3.5 New Components

The AI architecture introduces several new modules.

## Component 1 — Embedding Generator

Purpose:

Convert textual information into numerical vectors.

Input:

```
Question Title

Problem Description

Tags

Solution

Notes
```

Output:

```
[0.124,
-0.531,
0.943,
...
768 dimensions]
```

The embedding captures the **meaning** of the content, not just the exact words.

---

## Component 2 — Vector Database

Stores embeddings for fast semantic search.

Recommended options:

### ChromaDB

Advantages:

- Beginner friendly
- Local database
- Python support
- Metadata filtering
- Persistent storage

Best choice for this project.

---

### FAISS

Advantages:

- Extremely fast
- Lightweight
- Ideal for local search

Disadvantages:

- No built-in metadata storage

---

Recommendation:

```
Development → ChromaDB

Production → ChromaDB

Large Scale → Pinecone / Weaviate
```

---

The retriever performs semantic search.

Example:

Even if the word "graph" isn't in the title.

# 3.9 Why Vector Search?

Traditional SQL search:

```

```

Finds only exact matches.

Vector search understands meaning.


# 3.10 Metadata Filtering

Every embedding stores metadata.

Example:

```json
{
  "question_id": 56,
  "title": "Merge Intervals",
  "difficulty": "Medium",
  "language": "C++",
  "tags": [
    "Array",
    "Sorting"
  ],
  "timestamp": "2026-08-10",
  "github_url": "...",
  "submission_id": 9082345
}
```

Metadata allows filtering before semantic search.

Example:

```
Difficulty = Hard

AND

Language = C++

AND

Tag = Graph
```

Only matching documents are searched.

# 3.11 Choosing Top-K

Example:

```

```

Typical values:

- K = 3 → Short context
- K = 5 → Recommended
- K = 10 → Detailed analysis
