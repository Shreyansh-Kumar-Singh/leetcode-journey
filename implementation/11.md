# 11.9 Configuration Module

Instead of reading environment variables throughout the codebase, centralize them.

Directory:

```text
core/
```

Create:

```python
from dotenv import load_dotenv
import os

load_dotenv()

class Settings:

    APP_NAME = os.getenv("APP_NAME")

    APP_PORT = int(os.getenv("APP_PORT"))

    SQLITE_PATH = os.getenv("SQLITE_PATH")

    CHROMA_PATH = os.getenv("CHROMA_PATH")

    GEMINI_API_KEY = os.getenv("GEMINI_API_KEY")

settings = Settings()
```

Every module imports:

```python
from core.config import settings
```

# 11.2.5 Database Engine

Recommended configuration:

```python
engine = create_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False}
)
```

Reason:

FastAPI may access SQLite from multiple threads.

# 11.2.6 Session Factory

Instead of opening connections manually everywhere:

```
Request

↓

Session

↓

Repository

↓

Commit

↓

Close
```

Every request gets its own database session.

Benefits:

- Prevents connection leaks
- Easier testing
- Cleaner code

# 11.2.14 Dependency Injection

FastAPI provides dependency injection.

Instead of:

```

Every Route
```

```
Dependency

↓

↓

Route
```

Benefits:

- Cleaner code
- Easier testing
- Centralized session management

---

# 11.2.15 Repository Pattern

Routes should never execute SQL directly.

Wrong:

```
Route

↓

SQL Query
```

Correct:

```
Route

↓

Service

↓

Repository

↓

Database
```

Repository responsibilities:

- Read
- Insert
- Update
- Delete

No business logic.

# Best Practices

- Keep SQLite as the single source of truth.
- Treat ChromaDB as a rebuildable semantic index.
- Never access databases directly from API routes.
- Use dependency injection for database sessions.
- Initialize external services during startup.
- Expose a health endpoint for deployment monitoring.
- Centralize configuration and logging.

Following these practices will make the project easier to maintain and scale.
