# Section 15 — FastAPI Backend Architecture

> **Objective:** Build a scalable backend using FastAPI that serves as the central component of your AI-powered LeetCode Visualizer. This backend will expose REST APIs, manage data, interact with SQLite/PostgreSQL, communicate with ChromaDB, invoke the AI Agent, and return structured responses to the frontend.

---

# 15.1 Why Do We Need a Backend?

Currently your project looks like this:

```text
LeetCode
      │
      ▼
SQLite Database
      │
      ▼
GitHub Pages Dashboard
```

This architecture works for displaying charts.

However, if the user asks:

```
Explain my Binary Search solution.

Recommend Graph problems.

Why is DP my weakest topic?

Find problems similar to Two Sum.
```

Static HTML cannot perform these operations.

We need a backend.

---

# 15.2 Responsibilities of the Backend

The backend should handle:

```
Authentication

REST APIs

Database Operations

Embedding Generation

Vector Search

Recommendation Engine

AI Agent

LLM Communication

Analytics

JSON Responses
```

The frontend should never directly access the database.

# 15.4 Why FastAPI?

FastAPI is chosen because it provides:

```
High Performance

Automatic API Documentation

Type Validation

Async Support

Easy Integration

Modern Python Features
```

Compared to Flask, FastAPI provides built-in validation and OpenAPI documentation.

# 15.6 Layered Architecture

Instead of putting everything inside one file:

```
main.py

5000 lines
```

Separate responsibilities.

```
API Layer

↓

Service Layer

↓

Repository Layer

↓

Database
```

---

# 15.7 API Layer

Responsibilities:

```
Receive Request

Validate Input

Call Service

Return Response
```

No business logic should exist here.

---

# 15.8 Service Layer

Responsibilities:

```
Business Logic

AI Logic

Recommendation Logic

Analytics
```

This layer coordinates different modules.

---

# 15.9 Repository Layer

Responsibilities:

```
SQLite

PostgreSQL

CRUD Operations

Transactions
```

The service layer should never execute raw SQL directly.

---

# 15.10 Models vs Schemas

Models:

```
Represent database tables.
```

Schemas:

```
Represent API request and response formats.
```

Keep them separate.

---

# 15.13 Response Format

Always return structured JSON.

Example:

```json
{
    "success": true,
    "message": "Recommendations generated.",
    "data": {}
}
```

Avoid inconsistent response formats.

---

# 15.14 Error Responses

Example:

```json
{
    "success": false,
    "error": "Problem not found."
}
```

Consistent error handling improves frontend integration.

---

# 15.15 Dependency Injection

FastAPI supports dependency injection.

Typical dependencies:

```
Database Connection

Current User

Configuration

Logger
```

This avoids global variables.

---

# 15.16 Configuration

Store settings centrally.

Example:

```
Database URL

LLM Provider

API Keys

Embedding Model

Vector DB Path
```

Do not hardcode configuration values.

---

# 15.17 Database Connection

The backend should create one reusable connection pool.

Avoid:

```
New connection

↓

Every request
```

Reuse connections whenever possible.

---

# 15.18 Async Processing

Some tasks are slow:

```
LLM Requests

Embedding Generation

Vector Search
```

Use asynchronous APIs where appropriate to improve throughput.

---

# 15.19 Background Tasks

Some operations should happen after returning a response.

Examples:

```
Generate Embeddings

Refresh Statistics

Rebuild Recommendations

Sync LeetCode
```

Background execution keeps APIs responsive.

---

# 15.20 API Versioning

Organize endpoints:

```
/api/v1/chat

/api/v1/analytics

/api/v1/recommendations
```

Future versions can evolve without breaking existing clients.

---

# 15.21 Logging

Log useful information:

```
Endpoint

Latency

Errors

User ID

Request ID
```

Do not log secrets.

---

# 15.22 Middleware

Middleware can handle:

```
Logging

Authentication

CORS

Compression

Request Timing
```

Executed before and after every request.

---

# 15.23 Validation

Use request validation.

Example:

```
Question

↓

Must not be empty

↓

Maximum Length

↓

Valid JSON
```

Reject invalid input early.

---

# 15.24 Security

Protect against:

```
SQL Injection

Invalid Input

Unauthorized Access

Rate Abuse
```

Validation and authentication are essential.

---

# 15.25 API Documentation

FastAPI automatically generates:

```
Swagger UI

OpenAPI Specification
```

Developers can test APIs directly from the browser.
