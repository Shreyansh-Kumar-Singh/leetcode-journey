# 17.2 Why ChromaDB?

A normal SQL database stores:

```
Rows

Columns

Indexes
```

A vector database stores:

```
Embeddings

Metadata

Similarity Index
```

Instead of answering:

```
WHERE title = 'Two Sum'
```

it answers:

```
Find documents that are semantically similar.
```

# 17.11 Metadata

Along with every embedding, store metadata.

Example:

```json
{
  "problem_id": 56,
  "title": "Merge Intervals",
  "difficulty": "Medium",
  "language": "C++",
  "tags": [
      "Array",
      "Sorting"
  ]
}
```

Metadata enables filtering without reading the full document.

---

# 17.12 Chroma Collection

Think of a collection like a SQL table.

Example:

```
leetcode_problems
```

Every embedded problem is stored inside this collection.

---

# 17.13 IDs

Every document must have a unique ID.

Good examples:

```
problem_1

problem_25

problem_144
```

Avoid duplicate IDs because updates become difficult.

---

# 17.14 Indexing Pipeline

```text
SQLite

↓

Read Problems

↓

Create Documents

↓

Generate Embeddings

↓

Store in ChromaDB
```

This pipeline runs whenever new problems are synchronized.

---

# 17.15 Initial Indexing

The first run performs:

```
All Problems

↓

Embed

↓

Store
```

This may take several minutes depending on dataset size.

---

# 17.16 Incremental Updates

Daily synchronization should only process:

```
New Problems

Updated Notes

Modified Solutions
```

Avoid rebuilding the entire index every day.

---

# 17.17 Updating Documents

When a solution changes:

```
Delete Old Embedding

↓

Generate New Embedding

↓

Insert Updated Version
```

Keep the vector database synchronized with SQLite.

---

# 17.18 Deleting Documents

If a document is removed:

```
SQLite Delete

↓

Remove Embedding

↓

Refresh Index
```

Never leave orphaned vectors.

---

# 17.19 Batch Embedding

Instead of embedding:

```
1

↓

2

↓

3
```

Generate embeddings in batches:

```
Batch

↓

Embedding Model

↓

Vectors
```

Batching improves throughput.

# 17.22 Similarity Search

Every stored vector receives a similarity score.

Example:

| Problem | Score |
|----------|------:|
| Number of Islands | 0.95 |
| Clone Graph | 0.91 |
| Course Schedule | 0.89 |
| Pacific Atlantic | 0.81 |

Higher scores indicate stronger semantic similarity.

# 17.24 Rebuilding the Index

Rebuild only when:

```
Embedding Model Changes

Large Dataset Changes

Metadata Format Changes
```
