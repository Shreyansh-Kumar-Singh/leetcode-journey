# Section 22 — LLM Integration (Provider-Agnostic Architecture)

> **Objective:** Build a provider-independent LLM layer so your LeetCode AI Assistant can work with OpenAI, Google Gemini, Anthropic Claude, Ollama, or any future model without changing the RAG or Agent code.

---

# 22.1 Why Abstract the LLM?

Many beginners write code like this:

```python
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(...)
```

Then, if they later decide to use Gemini or Claude, they must rewrite large parts of the application.

Instead, build this architecture:

```text
                AI Agent
                   │
                   ▼
             LLM Interface
                   │
        ┌──────────┼───────────┐
        ▼          ▼           ▼
     OpenAI     Gemini      Ollama
```

Only the provider changes.

# 22.3 Base Interface

Create:

```
base.py
```

```python
from abc import ABC, abstractmethod

class BaseLLM(ABC):

    @abstractmethod
    def generate(

        self,

        system_prompt,

        user_prompt

    ):

        pass
```

Every provider implements this interface.

---

# 22.4 Why Interfaces Matter

Without an interface:

```
Agent

↓

OpenAI SDK
```

With an interface:

```
Agent

↓

BaseLLM

↓

Provider
```

The agent never depends on provider-specific code.

# 22.5 Environment Variables

Store configuration in `.env`.

Example:

```text
LLM_PROVIDER=openai

LLM_MODEL=gpt-5.5

OPENAI_API_KEY=...

GEMINI_API_KEY=...

ANTHROPIC_API_KEY=...

OLLAMA_HOST=http://localhost:11434
```

Never hardcode secrets in Python files.

---

# 22.6 Configuration Loader

Create:

```
config.py
```

Example:

```python
import os
from dotenv import load_dotenv

load_dotenv()

LLM_PROVIDER = os.getenv("LLM_PROVIDER")

LLM_MODEL = os.getenv("LLM_MODEL")
```

This keeps configuration centralized.

---

# 22.7 Factory Pattern

Create:

```
factory.py
```

Purpose:

```
Configuration

↓

Correct Client

↓

Return BaseLLM
```

Example:

```python
from .config import LLM_PROVIDER

def create_llm():

    if LLM_PROVIDER == "openai":

        return OpenAIClient()

    if LLM_PROVIDER == "gemini":

        return GeminiClient()

    if LLM_PROVIDER == "ollama":

        return OllamaClient()

    raise ValueError("Unsupported provider")
```

The rest of your application simply calls:

```python
llm = create_llm()
```

---

# 22.8 OpenAI Client

Conceptually:

```python
class OpenAIClient(BaseLLM):

    def generate(

        self,

        system_prompt,

        user_prompt

    ):

        ...
```

The implementation should:

- Accept system and user prompts.
- Call the provider's chat API.
- Return only the generated text.
- Hide SDK-specific details from the rest of the application.

---

# 22.9 Gemini Client

The interface should be identical.

```python
class GeminiClient(BaseLLM):

    def generate(

        self,

        system_prompt,

        user_prompt

    ):

        ...
```

The agent does not know whether the answer came from OpenAI or Gemini.

---

# 22.10 Ollama Client

Ollama allows running local models.

Architecture:

```text
Application

↓

HTTP

↓

Ollama

↓

Local Model
```

Advantages:

```
No API cost

Offline

Private

Good for experimentation
```

Trade-offs include larger hardware requirements and varying model quality.

---

# 22.11 Unified Response

Every client should return the same structure.

Example:

```python
{
    "text": "...",

    "model": "...",

    "provider": "...",

    "usage": {

        "input_tokens": ...,

        "output_tokens": ...

    }
}
```

Even if a provider does not expose all fields, keep the interface as consistent as possible.

---

# 22.12 Why Normalize Responses?

Different providers return different JSON formats.

Normalize them into a single structure so the agent never needs provider-specific logic.

---

# 22.13 Prompt Structure

Your prompts should always follow the same format:

```
System Prompt

↓

User Prompt

↓

Retrieved Context
```

Avoid mixing provider-specific prompt templates throughout the codebase.

---

# 22.14 System Prompt

Example:

```
You are an AI assistant for a personal
LeetCode analytics platform.

Use retrieved context when available.

Do not fabricate statistics.

If information is missing,
say that it is unavailable.
```

The system prompt defines behavior, not facts.

---

# 22.15 User Prompt

Example:

```
Question:

Recommend Graph problems.

Context:

...

Answer:
```

Keep the user prompt focused on the specific task.

---

# 22.16 Temperature

Temperature controls randomness.

General guidance:

```
0.0

↓

Deterministic
```

```
1.0

↓

More Creative
```

For your project:

```
0.1–0.3
```

is usually appropriate because factual consistency is more important than creativity.

---

# 22.17 Max Tokens

Every request should define a maximum output size.

For example:

```
300–600 tokens
```

for ordinary answers.

This helps control cost and latency.

---

# 22.18 Retry Logic

Network calls can fail.

A simple retry strategy:

```
Attempt

↓

Failure

↓

Short Delay

↓

Retry

↓

Maximum Attempts

↓

Return Error
```

Do not retry indefinitely.

---

# 22.19 Timeout

Always configure request timeouts.

Without a timeout:

```
Server waits forever.
```

With a timeout:

```
Request

↓

Timeout

↓

Graceful Error
```

---

# 22.20 Rate Limiting

Some providers enforce rate limits.

Handle them gracefully:

```
Too Many Requests

↓

Backoff

↓

Retry Later
```

Do not continuously resend failed requests.

---

# 22.21 Streaming Responses

Instead of waiting for the complete response:

```
User

↓

LLM

↓

Entire Response
```

you can stream tokens:

```
User

↓

LLM

↓

Token

↓

Token

↓

Token
```

Streaming improves perceived responsiveness.

---

# 22.22 Caching

Many users ask repeated questions.

Cache responses when appropriate.

Example:

```
Question

↓

Hash

↓

Cache?

↓

Yes → Return Cached Result

No → Call LLM
```

Avoid caching highly personalized responses that change frequently.

---

# 22.23 Cost Optimization

Do not call the LLM for simple deterministic queries.

Instead:

```
"How many Easy problems?"

↓

SQLite

↓

Return Count
```

Use the LLM when reasoning or explanation is needed.

---

# 22.28 Best Practices

```
✓ Separate provider code from business logic.

✓ Store secrets in environment variables.

✓ Normalize provider responses.

✓ Configure retries and timeouts.

✓ Log useful metrics.

✓ Use low temperature for factual tasks.

✓ Keep prompts centralized.

✓ Make provider switching a configuration change, not a code change.
```
