# Section 24 — Authentication, Multi-User Support & Production Deployment

> **Objective:** Transform your LeetCode AI Assistant from a personal project into a production-ready SaaS application that supports multiple users, secure authentication, cloud deployment, and scalable architecture.

---

# 24.1 Current Architecture

Currently your application works like this:

```text
                 You
                  │
                  ▼
          LeetCode Cookies
                  │
                  ▼
            Sync Script
                  │
                  ▼
              SQLite
                  │
                  ▼
         GitHub Pages Dashboard
                  │
                  ▼
              AI Backend
```

This is perfect for a personal portfolio.

However, multiple users cannot use it.

---

# 24.2 Production Goal

We want this architecture:

```text
                Internet
                    │
                    ▼
              Load Balancer
                    │
                    ▼
              FastAPI Server
                    │
      ┌─────────────┼─────────────┐
      ▼             ▼             ▼
 Authentication   PostgreSQL   ChromaDB
      │             │             │
      └─────────────┼─────────────┘
                    ▼
                  AI Agent
                    │
                    ▼
                   LLM
```

Now every user has their own data.

---

# 24.3 Why SQLite Is Not Enough

SQLite is excellent for:

```
Personal Projects

Portfolio

Local Development

Small Desktop Apps
```

But it has limitations for:

```
Many concurrent users

Cloud deployment

Horizontal scaling

High write throughput
```

For production, PostgreSQL is generally a better fit.

---

Instead of:

```

Create:

```

problems

# 24.8 Password Storage

Never store:

```
password = "mypassword123"
```

Store:

```
Password

↓

Salt

↓

Hash

↓

Database
```

Use a secure password hashing algorithm (e.g., Argon2 or bcrypt) rather than general-purpose hashing.

# 24.12 FastAPI Dependency

```python

    verify_jwt()

```

# 24.13 User Isolation

Suppose:

```
Alice

Bob
```

Alice must never see:

```
Bob's submissions

Bob's recommendations

Bob's embeddings
```

Every SQL query must filter by:

```
user_id
```

---

# 24.14 ChromaDB Separation

Each user's embeddings should remain isolated.

Options:

```
Collection Per User
```

or

```
Single Collection

+

Metadata

user_id
```

The second approach usually scales better for many users.

# 24.18 Cookie Security

Your existing sync script uses LeetCode cookies.

Never:

```
Store cookies in GitHub.

Store cookies in JSON.

Send cookies to frontend.
```

Cookies should remain encrypted or securely stored on the backend.
