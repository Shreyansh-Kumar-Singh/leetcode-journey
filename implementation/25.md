# Section 25 — Production Monitoring, Evaluation & AI Observability

> **Objective:** Learn how to measure, debug, and continuously improve your AI system after deployment. Building an AI application is only half the work—the other half is ensuring it remains accurate, fast, reliable, and cost-effective over time.

---

# 25.1 Why Monitoring Matters

Imagine your AI assistant suddenly starts recommending unrelated problems or giving incorrect statistics.

Without monitoring:

```
User
 ↓
Bad Answer
 ↓
User Leaves
```

With monitoring:

```
User
 ↓
Bad Answer
 ↓
Logs
 ↓
Tracing
 ↓
Root Cause
 ↓
Fix
```

Monitoring transforms debugging from guesswork into engineering.

# 25.3 What Should Be Measured?

Every request should collect:

```
Timestamp

User ID

Query

Intent

Tools Used

Retrieved Documents

LLM Model

Latency

Token Usage

Cost

Success

Errors
```

These metrics help identify bottlenecks and failures.

# 25.4 Request Tracing

Each request should have a unique trace ID.

Example:

```
Request ID

↓

Agent

↓

SQL Tool

↓

Retriever

↓

LLM

↓

Response
```

If a user reports an issue, you can trace the exact execution path.

# 25.5 Logging Levels

Use different logging levels:

```
DEBUG

INFO

WARNING

ERROR

CRITICAL
```

Example:

```
INFO:
Retrieved 5 documents.

WARNING:
Retriever returned no documents.

ERROR:
LLM API timeout.
```

# 25.6 Latency Monitoring

Track latency for every stage:

```
Database Query

Retriever

Embedding

LLM

Total Response
```

Example:

```
SQL           18 ms

Retriever     75 ms

LLM        1,650 ms

Total      1,820 ms
```

This quickly identifies slow components.

# 25.9 Retrieval Metrics

RAG quality depends on retrieval.

Measure:

```
Retrieved Documents

Relevant Documents

```

Good retrieval reduces hallucinations.

---

# 25.10 Retrieval Precision

Concept:

```
Relevant Retrieved

───────────────

Total Retrieved
```

Higher precision means fewer irrelevant chunks.

---

# 25.11 Retrieval Recall

Concept:

```
Relevant Retrieved

───────────────

Relevant Available
```

Higher recall means the retriever finds more useful information.

---

# 25.12 Hallucination Detection

The LLM should not invent facts.

Example:

Bad:

```
You solved 150 Graph problems.
```

Database:

```
8 Graph problems
```

↓

Hallucination.

One strategy is to compare generated facts against structured tool outputs before returning them.

---

# 25.13 Source Verification

Every AI answer should include:

```

↓

Generated Answer

↓

```

Users should be able to inspect where information came from.

# 25.14 Prompt Versioning

Store versions:

```

v2

v3
```

This makes regressions easier to investigate.

```
Prompt B
```

```
Latency
```
