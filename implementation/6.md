# Section 6 — Retrieval Pipeline & Prompt Engineering

---

# Overview

The Retrieval Pipeline is the intelligence layer of the system.

The embedding pipeline stores knowledge.

The retrieval pipeline **finds the right knowledge**.

Finally, Prompt Engineering instructs the LLM how to use that knowledge.

Without retrieval:

```
User

↓

LLM

↓

Generic Answer
```

With Retrieval-Augmented Generation:

```
User

↓

Retriever

↓

Relevant Documents

↓

Prompt Builder

↓

LLM

↓

Personalized Answer
```

This is what makes the AI behave like **your personal LeetCode mentor** instead of a generic chatbot.

# 6.3 Query Preprocessing

Before searching, normalize the query.

Tasks:

- Remove extra whitespace
- Convert to lowercase (if appropriate)
- Detect entities
- Detect intent
- Extract filters

Example

Input:

```
Show all Hard Graph questions solved in July.
```

Output

```json
{
  "intent": "search",
  "difficulty": "Hard",
  "topic": "Graph",
  "month": "July",
  "query": "graph questions solved in july"
}
```

# 6.4 Intent Detection

Different questions require different pipelines.

| User Question | Intent |
|--------------|---------|
| Explain my solution | Explain |
| Find similar problems | Similarity Search |
| Study plan | Recommendation |
| Weak topics | Analytics |
| Interview me | Interview Mode |
| Weekly summary | Report Generation |

Example:

```
Explain Merge Intervals

↓

Intent

↓

Explain Solution
```

This allows specialized prompts.

---

# 6.5 Metadata Filtering

Before semantic search, apply filters.

Example:

```
Hard

Language = C++

Topic = Graph
```

Instead of searching every document, search only matching documents.

Workflow:

```
Metadata Filter

↓

Candidate Documents

↓

Vector Search

↓

Top Results
```

This improves both speed and accuracy.

---

# 6.6 Query Embedding

Convert the user's question into an embedding.

Example:

```python
query = "Explain my Merge Intervals solution"

query_embedding = model.encode(query)
```

Now both the query and stored documents exist in the same vector space.

---

# 6.7 Similarity Search

Search ChromaDB using the query embedding.

Example:

```python
results = collection.query(
    query_embeddings=[query_embedding],
    n_results=5
)
```

Example returned documents:

```
Merge Intervals

Insert Interval

Non-overlapping Intervals

Meeting Rooms

Meeting Rooms II
```

# 6.8 Re-ranking (Optional but Recommended)

Vector search retrieves candidates.

A second model can reorder them.

```
Query

↓

Vector Search

↓

Top 10

↓

Cross Encoder

↓

Best 5
```

Benefits:

- Higher accuracy
- Better explanations
- More relevant context

Future enhancement.

# 6.9 Context Construction

Do **not** send the entire database to the LLM.

Instead, build a compact context.

Example:

```
Question

Merge Intervals

Difficulty

Medium

Tags

Array

Sorting

Your Solution

...

Time Complexity

O(n log n)

Space Complexity

O(1)
```

Repeat for each retrieved document.

# 6.10 Prompt Builder

The prompt builder combines:

- System instructions
- Retrieved context
- User question

Template:

```
System

You are an AI coding mentor.

Use ONLY the provided context.

If the answer is unavailable,
say that the information does not exist.

-----------------------

Context

<Document 1>

<Document 2>

<Document 3>

-----------------------

User

Explain my solution.
```

This is one of the most important parts of the RAG system.

---

# 6.11 Prompt Design Principles

Every prompt should instruct the LLM to:

- Use only retrieved information.
- Avoid making up facts.
- Mention uncertainty.
- Explain clearly.
- Be concise.
- Suggest improvements when appropriate.

Example rules:

```
Never invent solutions.

Never claim a question was solved if
it is not in the retrieved context.

Always mention complexity if available.

Suggest optimization opportunities.
```

---

# 6.12 Context Window Management

LLMs have context limits.

Instead of sending everything:

```
500 Questions

↓

Top 5 Retrieved

↓

Prompt
```

Only the most relevant information is sent.

Typical context size:

```
3–5 retrieved documents
```

---

# 6.13 Hallucination Prevention

One of the biggest advantages of RAG is reducing hallucinations.

Strategies:

### 1. Restrict responses to retrieved context

```
Answer ONLY from context.
```

---

### 2. Mention missing information

Example:

```
I could not find a solution for this question in your history.
```

instead of inventing an answer.

---

### 3. Retrieve before generating

Never call the LLM directly.

Always:

```
Retrieve

↓

Generate
```

# 6.19 Why This Design?

This architecture separates responsibilities:

- **SQLite** stores structured data.
- **ChromaDB** performs semantic retrieval.
- **Retriever** selects relevant context.
- **Prompt Builder** formats high-quality prompts.
- **LLM** focuses only on reasoning.

This separation makes the system modular, testable, and easy to extend.
