# Section 8 — Backend Architecture & API Design

---

# Overview

The backend is the **central orchestration layer** of the project.

It connects all components:

- LeetCode Scraper
- SQLite Database
- ChromaDB
- AI Agents
- LLM
- GitHub Automation
- Frontend Dashboard

Unlike the current implementation where everything is executed as standalone scripts, the new system will expose a **REST API** using **FastAPI**.

This allows:

- Web frontend
- Mobile applications
- CLI tools
- Future browser extensions

to use the same backend.

# 8.4 Layered Architecture

Instead of writing all logic inside API routes, responsibilities should be separated.

```
Client

↓

API Layer

↓

Service Layer

↓

Repository Layer

↓

Database
```

---

## API Layer

Responsibilities:

- Receive request
- Validate input
- Call service
- Return response

No business logic.

---

## Service Layer

Contains business logic.

Example:

```
Generate embeddings

Run scraper

Call LLM

Retrieve vectors

Generate report
```

---

## Repository Layer

Responsible for

- SQL queries
- ChromaDB operations

No AI logic.


# 8.18 Why This Architecture?

This design follows common backend engineering principles:

- **API Layer** handles HTTP requests.
- **Service Layer** contains business logic.
- **Repository Layer** abstracts database operations.
- **AI Layer** is isolated from the rest of the application.
- **Configuration** is centralized.
- **Background tasks** prevent slow user responses.
- **Caching** reduces LLM cost and latency.

This makes the backend maintainable, testable, and easy to scale.
